# Worker Django Version Mismatch

> [!warning] Severity: MEDIUM
> The worker Dockerfile pins Django 4.x while the API Dockerfile pins Django 5.1.7. The worker imports Django models from the API codebase.

## What's Wrong

```dockerfile
# simulation_worker/Dockerfile
RUN pip3 install ... "Django>=4.2,<5" djangorestframework ...

# backend/Dockerfile
RUN pip install Django==5.1.7 djangorestframework ...
```

The worker container bind-mounts `/backend` and imports Django ORM models via `simulation_worker/config.py`:

```python
django.setup()  # Bootstraps with worker's Django 4.x
# Then imports backend/api/models.py written for Django 5.x
```

## Impact

- If `models.py` uses any Django 5 API (e.g., `GeneratedField`, updated `JSONField` behaviour), the worker will crash at import time
- Subtle ORM behaviour differences between Django 4 and 5 could cause silent data corruption
- Migration files generated by Django 5 may not be readable by Django 4's migration framework

Currently works by coincidence — the models don't yet use any 5.x-specific features. But any backend model change risks breaking the worker.

## Fix

Both Dockerfiles should install the same Django version. Better: create `simulation_worker/requirements.txt` and pin all shared dependencies to exact versions matching the backend.

```dockerfile
# Both containers:
RUN pip install Django==5.1.7
```
